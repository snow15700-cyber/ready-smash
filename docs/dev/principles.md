# 게임 만들기 대원칙 (11/27 사용자와 정함)

'AI로 게임 만들기' 조언 중 **이 게임(웹 3D 탁구·광장·낚시, 교육생 10~20명, 1월 말까지 운영)에 맞는 것만** 골라 고쳐 적은 것.
새 기능을 기획·제작할 때 이 목록을 기준으로 삼는다. 안 맞는 항목(컨트롤러 지원, 롤백 넷코드, Blender·Mixamo 같은 외부 도구 작업 등)은 뺐다.

## 1. 말 말고 '목표 그림·숫자'로 정한다
- 새 모습은 **참고 그림(실제 게임 스크린샷·AI 이미지·기존 시안 페이지)을 먼저** 정하고, 한 장면부터 만들어 참고 그림과 나란히 비교한다.
- "시원하게", "빠르게" 대신 **숫자로** 정한다(공 속도, 판정 시간, 카메라 거리 등). 정한 숫자는 주제 문서에 적는다.
- 지금 하는 방식(시안 페이지 → 스크린샷 → 사용자가 고르기)을 그대로 유지한다.

## 2. 하나의 게임, 하나의 그림체
- 새 아이템·배경·건물은 **기존 그림체(낮은 폴리곤 + 둥근 모양 + 탁구 색 + 유리 UI)** 에 맞춘다. 두 그림체가 섞이면 미완성처럼 보인다.
- 색은 **소재에서** 가져온다(바다: 파랑·모래, 빵집: 갈색·크림).
- UI는 글자 대신 **그림(아이콘·키캡·손가락 그림)** 을 우선한다.
- **절대 어둡게 만들지 않는다.** 밤·비는 '색을 바꾸는 것'이지 안 보이게 하는 것이 아니다.
- 그림이 없다고 **상자로 때우지 않는다.** 만들기 어려우면 사용자에게 먼저 말한다.

## 3. 효과에는 '동작'이 있다
- 타격·연출은 **준비 동작 → 맞는 순간 잠깐 멈춤 → 돌아오기** 3박자를 갖춘다.
- 효과의 빛이 **바닥(탁구대·땅)에 비치면** 훨씬 그럴듯하다.

## 4. '지루한 10%'가 게임을 완성한다
- 로딩 화면, 메뉴 소리, 조작법 안내(PC 키보드·마우스 / 휴대폰 터치 둘 다)를 빠뜨리지 않는다.
- **UI와 소리는 모든 모드(혼자·1대1·2대2·광장·낚시)에서 같게.**
- 무거운 3D는 **한꺼번에 올리지 말고 나눠서** 준비한다(첫 화면 멈춤 방지).

## 5. 온라인: 세상이 아니라 '입력'을 보낸다
- 판정·물리는 **결정론적**(같은 입력 → 같은 결과)으로 두고, 네트워크로는 꼭 필요한 것만 보낸다(이미 지키는 규칙).
- **방장 탭이 뒤로 가면(다른 창 보기) 브라우저가 타이머를 느리게 한다.** 경기 진행이 멈추지 않게 대비한다(필요하면 Worker로 시계 돌리기 — 아직 안 함, 문제 생기면 우선 검토).
- 시험은 **탭 여러 개 + 가짜 지연(`?lag=`)** 으로: 방장이 나감, 누가 새로고침, 늦게 들어옴.

## 6. Claude는 게임을 직접 해 볼 수 없다
- Claude가 정한 숫자(속도·타이밍·소리 크기)는 **사람이 해 보기 전까지 추측**이다. 그래서 단계마다 사용자가 테스트한다(지금 방식 유지).
- 대신 게임이 **스스로 시험**하게 만든다: AI 상대(김제빵), 자동 플레이, 한 판 전체를 돌려 보는 점검.
- 이상한 느낌은 **재 본다**(예: "화면이 떨린다" → 몇 프레임에 몇 번 흔들리는지 숫자로).
- 움직임이 맞는지는 AI 판단(스크린샷 보고 판단)을 믿지 말고 사용자 눈으로 확인한다.

## 7. AI는 싸고, 안목은 비싸다
- "더 예쁘게"는 **여러 번 고치는 것을 미리 각오**한다(한 번에 끝나지 않음).
- 비슷한 장르의 잘 만든 게임을 **먼저 해 보면** 기획이 바뀔 수 있다 — 새 큰 기능 전에 참고 게임을 같이 정해 본다.

## 8. 소리·그림 출처
- 외부 그림·소리를 쓸 땐 **라이선스를 확인**하고, 출처를 문서에 적는다(지금은 소리를 Web Audio로 직접 만들어 씀).
- 무료(CC0)만 고집하다 게임이 나빠지면 안 된다 — 필요하면 사용자와 상의.
