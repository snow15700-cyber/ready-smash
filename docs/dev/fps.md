## 1. 한도 정리 (11/28 조사)
| 서비스 | 무료 한도 | FPS에 뜻하는 것 |
|---|---|---|
| Supabase Realtime | 월 메시지 200만 개, **초당 100개** (넘으면 연결 끊김). 방송 1번 = 보낸 사람 1 + 받는 사람 수만큼 셈 | **움직임을 Supabase로 보내면 안 됨.** 8명이 1초에 10번만 보내도 초당 600개 이상 → 바로 끊김 |
| Cloudflare TURN(서울 중계) | 월 1,000GB(SFU와 같이 씀), **Cloudflare에서 나가는 쪽만** 계산 | 작은 숫자만 보내면 거의 안 씀(아래 계산) |

→ **결론: 움직임·총알은 전부 선수끼리 직접 연결(WebRTC, 교실에선 서울 중계)로. Supabase는 방 만들기·연결 인사·시작·결과 저장만.**

## 2. 네트워크 설계 (용량 아끼는 핵심)
- **방장 한 명이 가운데(별 모양)**: 각자는 방장에게만 보내고, 방장이 모아서 한 번에 돌려줌.
  - 모두가 모두에게 보내는 방식보다 꾸러미 수가 훨씬 적음(8명: 56갈래 → 14갈래). 꾸러미마다 붙는 포장(약 60~80바이트)이 실제 내용보다 커서 이게 제일 중요.
  - 방장이 **심판**도 함(맞았는지 최종 인정) → 탁구의 `match.js` 방장 방식과 같음.
- **1초에 15번**, 숫자를 작게 줄여 보냄(위치·방향을 2바이트 정수로). 사람 1명 정보 ≈ 10바이트.
- **'안 와도 되는' 길로**: 위치는 늦게 온 건 버리는 데이터 채널(순서 X, 다시 보내기 X), 맞음·기절·점수는 '꼭 가는' 채널. 지금 `makeP2P`는 꼭 가는 채널 하나라 FPS용 채널을 하나 더 만든다.
- **지금 탁구처럼 Supabase 방송으로 같이 보내지 않기**(탁구는 두 길로 보내고 먼저 온 것을 씀 — FPS에선 이걸 끔).
- 용량 대략 계산(8명, 3분): 방장이 받는 것 7×15×≈75B + 7명이 받는 것 7×15×≈150B ≈ **초당 24KB → 한 판 약 4~5MB**. 하루 50판 ≈ 250MB, 한 달 ≈ 7GB(1,000GB의 1% 미만). Supabase는 한 판에 수십 개.
- 방장이 나가면: 그 판은 끝 (사용자 확정 11/28). 단, 잠깐 끊김은 '나감'으로 보지 않음(10장).

## 3. 타격감 — 느린 와이파이에서도 "쏜 즉시" 느낌
네트워크가 15번/초라도 손맛이 좋으려면 **내 화면에서는 기다리지 않게** 만든다.
- **내 움직임·내 총은 내 PC에서 바로** 처리(서버 답을 안 기다림).
- **쏜 사람 기준 판정**: 내 화면에서 맞았으면 → 바로 맞음 연출 → 방장에게 "몇 시 몇 분에 누구를 맞힘" 보냄 → 방장은 거리·연사 속도·그 순간 위치가 말이 되는지만 확인하고 인정. (드물게 거절되면 점수만 안 오르고 연출은 그대로)
- 다른 사람은 **0.1초 전 모습을 부드럽게** 이어 그림(뚝뚝 끊기지 않게).
- 즉발 총(맞는 즉시)이 이 방식에 가장 잘 맞음. 날아가는 공은 늦음이 보임.

손맛 연출(내 화면에만, 네트워크 0):
1. 쏠 때 반동(총 툭·화면 살짝 위로) + 총구 번쩍 + "탕/퐁" 소리
2. 맞으면 조준점 ✕ 번쩍 + "틱!" 맞음 소리(따로 들리게 높은 음)
3. 맞은 사람 몸이 움찔·색이 번쩍, 숫자 튀어 오름
4. 쓰러뜨리면 짧은 멈칫(0.05초) + 큰 소리 + 화면 가장자리 번쩍 + "1킬"→"2연속!" 글자
5. 내가 맞으면 맞은 쪽 방향 화면 가장자리 빨강/색 + 둔한 소리
6. 머리 맞히면 소리·✕가 다름(더 쨍함)

## 10. 느리고 자주 끊기는 교육장 와이파이 대비 (11/28 사용자 질문: "Cloudflare 조금 더 써도 됨")
**대답: 대비하면 괜찮다. Cloudflare 중계를 조금 더 쓰는 쪽으로.** 늘려도 한 달 30GB 정도(무료 1,000GB의 3%).

### 10-1. 공을 덜 잃게 — 용량을 더 쓰는 곳
- **1초에 15번 → 30번**: 더 부드럽고, 하나 잃어도 다음 것이 금방 옴.
- **겹쳐 보내기**: 꾸러미마다 바로 전 2개의 내 입력도 같이 실음 → 하나 잃어도 다음 꾸러미로 채움(꾸러미 수는 그대로라 Supabase 0, Cloudflare만 조금 더).
- 맞음·쓰러짐·점수 같은 중요한 소식은 '꼭 가는' 길 + 번호를 붙여 두 번 받으면 하나 버림.
- 계산: 4대4·3분에 약 15~20MB, 하루 50판 ≈ 한 달 30GB.

### 10-2. 잠깐 끊김은 '나감'이 아님
- **선수가 끊김**: 3초 동안은 그 자리에 서 있음(머리 위 📶). **15초 안에 돌아오면** 점수 그대로 이어서. 그 사이 자리는 **봇이 대신**(11장 봇을 재사용) ❓. 15초 넘으면 나감.
- **방장이 끊김**: 모두 화면에 "방장 연결 기다리는 중…" + 잠깐 멈춤. **5초 안에 돌아오면** 이어서, 넘으면 그 판 끝(사용자 확정 '방장 나가면 끝'). 끝난 판은 그때까지 점수로 결과 저장 ❓(또는 무효).
- 다시 들어오면 방장이 지금 상태 전체를 한 번 보내 줌.

### 10-3. 방장을 '연결이 제일 좋은 사람'으로
- 대기하는 동안 서로 몇 번 핑을 재서, **늦음·끊김이 가장 적은 사람**을 방장으로 자동 선택(탁구대에 먼저 선 사람이 아니라). 방장 PC가 제일 중요하기 때문.
- 연결이 너무 나쁜 사람은 발판에서 📶 빨강 표시 + "와이파이가 불안정해요" 안내(참가는 막지 않음).

### 10-4. 늦게 와도 덜 티 나게
- 다른 사람은 **0.1~0.2초 전 모습**을 이어 그림(와이파이가 흔들리면 저절로 조금 더 늦게 → 뚝뚝 끊김 대신 부드럽게).
- 쏜 사람 기준 판정은 **최대 0.25초 전까지만** 인정 → 많이 늦은 사람이 벽 뒤로 숨은 사람을 맞히는 억울함을 줄임.
- 화면 구석에 내 연결 상태(📶 초록/노랑/빨강).

### 10-5. 생각해 봤지만 안 쓰는 길: Cloudflare 서버(Durable Objects)가 방장
- 장점: 선수 PC가 방장이 아니니 '방장 끊김'이 없음.
- 안 쓰는 이유: ① 웹소켓(TCP)이라 끊김이 잦은 와이파이에서는 하나 잃으면 뒤 소식이 줄줄이 늦음(FPS에 나쁨). ② 무료는 하루 요청 10만 개(받는 웹소켓 메시지 20개 = 1개) → 8명·30번/초면 **하루 40~50판에서 막힘**(넘으면 그날은 오류). ③ 서버 코드를 새로 하나 더 관리.
- 나중에 방장 끊김이 실제로 자주 생기면 다시 생각.

## 11. 모드와 봇 (11/28 사용자 확정 + 제안)
### 11-1. 개인전 (최대 8명, 사람+봇 합쳐서)
- 모두가 적. 끝: **3분 또는 먼저 15킬** ❓ → 1·2·3등 표시.
- 다시 나오는 곳은 적이 가장 먼 곳 중 하나.

### 11-2. 팀전 (1대1 ~ 4대4)
- 3분, 많이 쓰러뜨린 팀 승리(같으면 무승부 또는 다음 1킬 승). 팀 색 두 개.
- 1대1도 됨(사람 2명이 붙거나, 사람 1명 + 봇).

### 11-3. 봇
- 발판에서 방장이 **'+ 봇'** 버튼으로 빈자리에 넣음(이름은 김제빵 가족? — 테마 정할 때 같이). 난이도 3단계(쉬움·보통·어려움): 반응 속도·조준 흔들림·머리 맞히는 비율만 다름.
- **봇은 방장 PC가 계산**하고 사람과 똑같이 위치를 보냄(봇 1개 = 사람 1명만큼 용량, 늘어나는 건 Cloudflare 조금).
- 움직임: 맵에 미리 찍어 둔 길 점을 따라 걷기, 적이 보이면 멈춰 쏘기, 맞으면 엄폐물로. 단순하게.
- **멀티플레이 전용 규칙 유지**: 사람이 최소 2명이어야 시작(봇만 데리고 혼자 하기 없음 ❓ — 팀전 1대1 '사람 1 + 봇'은 혼자 하기라서 안 되는 쪽이 기준과 맞음).
- 코인·업적: 봇을 쓰러뜨린 것은 **덜 주거나 안 줌** ❓(탁구에서 김제빵 낀 2대2 전적 제외와 비슷하게).
