# 경기 규칙·조작·동기화

> CLAUDE.md에서 옮겨 온 상세 기록. 작업할 때 필요한 부분만 읽는다. 새로 정해진 것도 여기에 적는다.

## 사용자가 확정한 결정 (바꾸기 전에 사용자에게 확인)
- 캐릭터: 흰색 몸통+흰색 머리만, 팔 없음, 탁구채만 떠 있음. **내 캐릭터는 반투명**(0.38), 상대·팀원은 불투명. 탁구채 기본은 빨강, 옷장에서 장착한 것으로 바뀐다(`items.js`).
- 체육관은 단순하게(벽, 나무 바닥, 강당 무대·커튼, 현수막만).
- 카메라: 어깨 뒤 낮게 + 공 따라가기 + 타격 시 흔들림 (`src/scene.js`의 `CAM`).
- 조작: **마우스를 누른 채로 위로 밀어 올리기** = 스윙. 클릭 직전 0.15초 ~ 직후 `HOLD`(0.09초)의 움직임을 본다. 위로 안 올리면 블록.
- 판정 범위(`physics.js`의 `WIN`/`WIN_LATE`, `judge`): 일찍 친 쪽 perfect 0.045 / good 0.1 / bad 0.17초, **늦게 친 쪽은 좁게** perfect 0.045 / good 0.08 / bad 0.14초(공이 몸을 지나간 뒤 넘어가지 않게, 사용자 확정). 늦게 0.14초를 넘으면 블록도 놓침.
- 방향: 올리는 방향으로 왼쪽/가운데/오른쪽 3방향만. 옆 이동이 위 이동의 **30%** 이상이면 좌우.
- 타구음은 클릭 즉시 로컬 재생. 방향을 읽는 HOLD 동안 공은 라켓에 머문 뒤 출발.
- 서브 토스 위속도 3.6 (약 0.8m 위로). 서브 헛스윙은 실점 없이 다시 토스.
- **서브는 두 번 튄다**(11/22 사용자 요청, test): 실제 탁구처럼 친 사람 쪽 탁구대(네트에서 1.0m, `SERVE_Z1`) → 네트 넘어 → 상대 탁구대. `physics.js`의 `planServe`가 첫 바운드 뒤 튀어 나가는 속도 `sv`를 미리 정한다(낮게 친 서브도 넘어가게, 게임용 물리). `sv`는 'shot' 이벤트에 실려(`ev.sv`) 모든 PC가 `simulate(..., {serve: sv})`로 같은 궤적을 만든다. 두 번째 구간 시간 `SERVE_T2`(perfect 0.46 / good 0.55 / bad 0.8 / block 0.7초)는 받는 사람에게 공이 오는 시각이 예전 서브와 거의 같게 맞춤. `findIdealHit`은 서브(`segs[0].serve`)면 친 사람 쪽 첫 바운드 1번을 정상으로 본다. 2v2 대각선 서브 규칙은 안 넣기로(사용자). 로비 배경 랠리도 같은 서브.
- 랠리 속도 증가: 구조는 있지만 **현재 0** (`src/match.js`의 `SPEED_STEP`). 인터넷 지연 때문에 계속 빨라지는 방식은 쓰지 않는다.
- 찬스볼·스매시 (1v1·2v2·AI, `match.js`의 `CHANCE_RALLY`/`SMASH_SPEED`/`SMASH_OUT`): 랠리 6회 넘은 뒤 BAD로 친 공 = 찬스볼 → 받는 사람 화면에만 '똑 똑 똑 띵' 신호음(마지막 높은 음 = perfect 타이밍, `audio.playCue`). 찬스볼을 PERFECT로 치면 스매시(그 공만 1.2~1.4배 랜덤, seed로 정해 모든 PC 같음). 스매시를 BAD(또는 GOOD 범위 밖 블록)로 받으면 아웃. **스매시는 높이 튀지 않고 낮고 빠르게 깔려 온다**(사용자 확정: 상대 탁구대 첫 바운드만 `physics.js`의 `E_SMASH` 0.4, 세그먼트 `smash` 표시). 이벤트 `shot`의 `kind`('chance'|'smash'|'out'), `computeShot`의 `incoming`/`dt`.
  - **찬스볼 물결 잔상**(사용자 확정 11/22, 정점까지로 바꾼 것 포함 main): 찬스볼은 친 순간 ~ **공이 가장 높이 올라갈 때(정점)까지** 보통 잔상(11/23 사용자 변경: 처음엔 첫 튐까지였음)(동그라미 7개) 대신 **하얀 물결 줄**이 살랑(꼬리 쪽으로 흐름). 정점을 지나면 0.12초 만에 사라지고 상대가 칠 때까지 **잔상 없음**. **색은 안 씀**(나중 궤적 아이템이 색을 바꿔도 모양으로 알아보게 — 궤적 아이템도 찬스볼일 땐 이 물결 규칙을 따를 것). '똑 똑 똑 띵' 박자(`playCue`와 같은 `CUE_GAP`)에 맞춰 반짝임: 정점 전엔 물결이 진하고 굵어지고, 정점 뒤엔 **공이 살짝 커지며 하얀 빛**(마지막 '띵'이 가장 밝음). **모두에게 보임**(1v1·2v2 선수·팀원·관전·혼자 하기) — 소리 신호는 그대로 받는 사람만. 보기만 다름. 코드: `game.js`의 `markChance`·`chanceFrame` → `scene.js`의 `chanceFx`(물결 띠는 화면 기준으로 흔들어 어느 시점에서도 보이게).
- **랠리 단계**(사용자 확정, main. 1v1·2v2만 — **혼자 하기(AI)는 사용자가 원래대로 되돌림**, `rallyTier`가 ai면 0): 랠리(양쪽 합계)가 **20·40·60회**에 닿으면 한 단계씩(`physics.js`의 `TIER_RALLY`, `rallyTier`). 단계마다 GOOD 범위만 PERFECT 쪽으로 좁아짐(일찍/늦게: 0.1/0.08 → 0.085/0.07 → 0.07/0.06 → 0.055/0.05, `GOOD_BY_TIER`). PERFECT·BAD 범위는 그대로. 블록: 1단계부터 GOOD 범위 밖 블록 = 찬스볼, 2단계부터 모든 블록 = 찬스볼(`computeShot`). GOOD이 좁아지니 스매시를 받을 때도 그만큼 BAD(아웃)가 쉬워짐. 따로 마무리 장치는 안 넣기로(사용자). 단계가 오르면 토스트 알림(`game.js`의 `TIER_TOAST`) + 랠리 표시 색이 진해짐(`.st-rally.lv1~3`). `judge`·`winFor`에 tier를 넘긴다(방장 `match.rally`와 참가자 `net.rally`가 같은 값이라 예측도 같음).
- 몰입 연출(1v1·2v2·AI): 랠리 6회부터 서서히 15회에 최대로 타구음·바운드음 에코(`audio.setEcho`) + 체육관 어두워짐(`world.setFocus`, 선수·탁구대·공은 그대로), 점수 나면 약 1초에 원래대로. 설정은 `game.js`의 `FOCUS`, `scene.js`의 `FOCUS_DARK`.
- 타이밍 링은 칠 자리가 화면 밖이어도 화면 가장자리 안쪽에 보인다(`game.js`의 `RING`).

## 동기화 규칙
- 방장(어느 쪽에 서든)이 공 궤적·판정·점수를 계산해 `{k:'ev', ev}`로 보낸다. 참가자는 `{k:'in', kind:'toss'|'swing', t, dir, up, from}`만 보낸다.
- 시각은 모두 **방장 시계** 기준. 상대 PC는 `game.offset`(ping 최소 RTT 표본)으로 변환한다.
- 상대 PC는 자기 타격을 `computeShot`으로 먼저 계산해 보여 주고, 방장 결과가 오면 맞춘다. 방장은 원격 선수 입력을 0.45초 더 기다린다.
- **늦게 온 타격은 공 출발을 늦춘다**(main 배포됨): 원격 선수의 스윙이 방장에게 늦게 도착하면 예전엔 공이 이미 그만큼 날아간 것으로 계산돼, 받는 사람 화면에 공이 거의 안 보이고 MISS가 났다(PERFECT 공 비행 약 0.73초, 스매시 0.6초인데 입력을 최대 0.68초까지 받아 줌). 이제 `match.swing(..., now)`에 도착 시각을 넘기면 공이 라켓에 더 머물다 출발해, 도착 시점에 날아간 시간이 `LATE_OK`(0.15초)를 넘지 않는다. 보통 지연(0.15초 이하)에선 그대로. 친 사람 화면은 방장 결과가 오면 공이 라켓 쪽으로 살짝 되돌아갔다 출발. Supabase 지역은 싱가포르. 서버 이전은 안 하기로. WebRTC 직접 연결은 처음엔 안 하기로 했다가, 강의실 측정(11/24) 결과가 훨씬 좋아서 적용하기로(아래).
- **와이파이 느림 대비 ①②**(11/21 사용자와 정함, test): 교육장 와이파이가 붐비면 방장이 친 공 소식이 받는 사람에게 늦게 와서 공이 순간이동하거나 안 보인 채 지나갔다.
  - ① **받는 사람 쪽 지연만큼 출발 늦추기**: 참가자 PC가 최근 ping 왕복 시간 12개의 75% 지점 ÷ 2(`room.js`의 `typicalLag`)를 ping에 `lat`로 실어 보내고, 방장은 `room.lag[id]`에 둔다. `Match`의 `lagOf(side, slot)` → `hit()`에서 받을 사람이 네트워크 너머면 hold에 그만큼(최대 `RECV_LAG_MAX` 0.2초) 더한다. 방장 화면에서는 공이 라켓에 잠깐 더 머문다(판정과 무관). 2v2에서 참가자 → 참가자 공은 친 사람 예측(HOLD만)과 달라져 살짝 되돌아갔다 출발.
  - ② **네트워크 렛**: 받는 사람 PC가 'shot'을 받았을 때 공이 이미 `LET_LATE`(0.3초) 넘게 날아갔으면 `{k:'in', kind:'late', idx}`를 보낸다. 방장은 그 공을 놓치면(miss) 실점 대신 `let` 이벤트 → 점수 없이 같은 서버가 다시 서브(1.6초 뒤). 놓친 뒤 알림이 와도 점수가 나기 전(0.9초)이면 렛으로 바꾼다. 선수마다 한 경기 `LET_MAX` 3번까지, 그다음은 원래대로 실점. 화면 토스트 '📶 내/상대/팀원 연결이 늦어서 다시 서브! (점수 없음)'. 받아쳤으면 그대로 진행. 알림은 믿는 방식(친구끼리 게임).
  - 로컬 시험: 방장 탭에 `?rtc=0&lag=700`을 붙이면 렛이 난다(방장 소식만 0.7초 늦음). WebRTC 직접 연결이 켜져 있으면 `?lag`는 서버 길만 늦춰서 렛이 안 난다.
- **WebRTC 직접 연결**(11/24 사용자와 정함 — ① 1대1 · ② 2대2 · ③ 정리 test, **사용자가 나중에 한 번에 테스트**)
  - 왜: 경기 소식이 늘 싱가포르 Supabase를 거쳐서 같은 교실 안인데도 늦었다. 강의실 와이파이에서 측정 페이지로 재 보니 직접 연결이 되고 훨씬 빨랐다(사용자 확인, 11/24).
  - 어떻게(`src/net.js`의 `joinRoom(..., { rtc: true })` + `makeP2P`): 경기 채널로 연결 정보(offer/answer/ice, `{k:'_rtc', to, from, t}`)를 주고받아 선수끼리 DataChannel(순서대로·빠짐없이)을 연다. id가 작은 쪽이 건다, 실패하면 3초 뒤 다시(3번까지). STUN만(구글), TURN 없음.
  - **모든 소식을 서버 채널과 직접 길 둘 다로 보낸다**(`_f` 보낸 사람.새로고침 표시·`_s` 번호를 붙임). 받는 쪽 `fresh()`가 먼저 온 것만 쓰고 두 번째는 버린다. 두 길 모두 순서대로 오므로 번호가 조금 엇갈릴 뿐 → 최근 번호만 기억. 그래서
    - 직접 연결이 안 붙어도(LTE·다른 와이파이·기기끼리 막힌 와이파이) 그대로 서버로 경기한다(따로 길 바꾸기 없음).
    - 관중(listen)은 지금처럼 서버로만 듣는다. Supabase 보내는 양도 그대로(서버로는 한 번).
    - `room.js`의 메시지 처리(ping/pong·go·ev·in·skip)는 하나도 안 바뀜. 시계 맞추기 ping도 빠른 길로 와서 offset·`typicalLag`(와이파이 느림 대비 ①)가 저절로 작아진다.
  - 켜는 곳: `room.js`의 `useRtc` = 경기 채널에 들어오는 사람이 2명 이상(1대1·2대2·김제빵 낀 2대2). 4명이면 서로 다 연결(6개), 김제빵은 방장 PC 안이라 연결 없음. 광장·로비·관중석 채널은 늦어도 티가 안 나서 서버 그대로.
  - 경기 화면 왼쪽 위 `#net-pill`(사용자: 보이게). `onDirect({ n, of })` = 다른 선수 of명 중 n명과 직접 → 모두 '⚡ 직접 연결'(초록 테) / 일부 '⚡ 일부 직접 (n/of)'(노란 테) / 없음 '🌐 서버 경유'.
  - 시험: `?rtc=0`이면 직접 연결을 끔(예전 방식과 비교). 로컬(같은 브라우저 탭끼리)에서도 직접 연결이 붙어서 `npm run check`의 광장 1대1 단계가 '⚡ 직접 연결'을 확인한다. 디버그 `window.__smash.room.link.direct()`.
  - **11/24 사용자 제보: test에서 1대1이 '🌐 서버 경유'로만 뜸** — 원인 아직 모름(실제 서버·교실 PC에서만 생김, 로컬 점검은 직접 연결됨). 고친 것·넣은 것:
    - 연결 요청(offer)보다 먼저 온 주소 정보(ice)를 버리던 것 → 모아 뒀다가 씀(`early`). 주소 정보 처리 오류는 기록.
    - 거는 쪽이 9초 안에 안 열리면 처음부터 다시 걸기(`WATCH`, 3번까지 — 서버 소식 하나가 빠졌을 때).
    - **진단**: 경기 화면 연결 표시(`#net-pill`)를 누르면 `#net-diag`에 상대마다 거는/받는 쪽·시도 횟수·요청/답 주고받음·보낸/받은 주소 종류(host·srflx)·연결 상태·**추정 이유**. 콘솔에도 `[직접 연결]` 줄. `link.rtcInfo()`.
