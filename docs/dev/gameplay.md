# 경기 규칙·조작·판정·동기화

> **지금 모습만**(11/27 정리). 아래는 모두 **사용자 확정** — 바꾸기 전에 사용자에게 확인.
> 매 프레임 `game.decideHit` → `match.update` → `game.update` 순서(느린 PC에서 늦은 스윙이 버려지지 않게). 판정·물리는 결정론적.

## 1. 캐릭터 · 카메라
- 흰 몸통 + 흰 머리, 팔 없음, 탁구채만 떠 있음. **내 캐릭터는 반투명**(0.38), 상대·팀원은 불투명. 탁구채·몸 등은 꾸미기대로(`items.js`, 보기만 다름).
- 카메라: 어깨 뒤 낮게 + 공 따라가기 + 타격 때 흔들림(`scene.js CAM`).
- 타이밍 링은 칠 자리가 화면 밖이어도 가장자리 안쪽에 보임(`game.js RING`).

## 2. 조작 · 판정
- **마우스를 누른 채 위로 밀어 올리기 = 스윙.** 누르기 직전 0.15초 ~ 직후 `HOLD` 0.09초의 움직임을 봄. 위로 안 올리면 블록.
- **방향 3개**: 옆 이동이 위 이동의 **30%** 이상이면 왼쪽/오른쪽, 아니면 가운데.
- 판정(`physics.js WIN`/`WIN_LATE`, `judge`): 일찍 친 쪽 perfect 0.045 / good 0.1 / bad 0.17초, **늦게 친 쪽은 좁게** 0.045 / 0.08 / 0.14초(공이 몸을 지나간 뒤 넘어가지 않게). 늦게 0.14초를 넘으면 블록도 놓침.
- 타구음은 누르는 즉시 내 PC에서. 방향을 읽는 HOLD 동안 공은 라켓에 머문 뒤 출발.
- 서브 토스 위 속도 3.6(약 0.8m). 서브 헛스윙은 실점 없이 다시 토스.
- **서브는 두 번 튐**(실제 탁구처럼): 친 사람 쪽(네트에서 1.0m, `SERVE_Z1`) → 상대 쪽. `planServe`가 첫 바운드 뒤 속도 `sv`를 정하고 'shot'에 실어(`ev.sv`) 모든 PC가 같은 궤적. 두 번째 구간 `SERVE_T2`(perfect 0.46 / good 0.55 / bad 0.8 / block 0.7초). 2대2 대각선 서브 규칙은 안 넣음.
- 랠리가 빨라지는 장치는 구조만 있고 **0**(`match.js SPEED_STEP`) — 인터넷 지연 때문에 안 씀.

## 3. 찬스볼 · 스매시 (1대1·2대2·혼자 하기)
- 랠리 6회 넘은 뒤 BAD로 친 공 = **찬스볼** → 받는 사람 화면에만 '똑 똑 똑 띵'(마지막 높은 음 = perfect 타이밍, `audio.playCue`).
- 찬스볼을 PERFECT로 치면 **스매시**(그 공만 1.2~1.4배, seed로 모든 PC 같음). **낮고 빠르게 깔려 옴**(상대 첫 바운드만 `E_SMASH` 0.4). 스매시를 BAD(또는 GOOD 밖 블록)로 받으면 아웃. 이벤트 `shot.kind` 'chance'|'smash'|'out'.
- **찬스볼 물결 잔상**: 친 순간 ~ **정점까지** 보통 잔상 대신 **하얀 물결 줄**, 정점 뒤엔 잔상 없음 + 공이 살짝 커지며 하얀 빛('띵'이 가장 밝음). **색은 안 씀**(나중 궤적 아이템도 찬스볼일 땐 이 물결 규칙을 따를 것). 모두에게 보임(소리는 받는 사람만). `game.js markChance·chanceFrame` → `scene.js chanceFx`.

## 4. 랠리 단계 (1대1·2대2만, 혼자 하기는 안 함)
- 랠리(양쪽 합계) **20·40·60회**에 한 단계씩(`physics.js TIER_RALLY`·`rallyTier`). GOOD 범위만 좁아짐(일찍/늦게 0.1/0.08 → 0.085/0.07 → 0.07/0.06 → 0.055/0.05, `GOOD_BY_TIER`). 1단계부터 GOOD 밖 블록 = 찬스볼, 2단계부터 모든 블록 = 찬스볼. 단계 토스트 + 랠리 표시 색(`.st-rally.lv1~3`).

## 5. 몰입 연출
- 랠리 6회부터 15회까지 서서히 타구음·바운드음 에코(`audio.setEcho`) + 배경 어두워짐(`world.setFocus`, 선수·탁구대·공은 그대로), 점수 나면 약 1초에 원래대로. `game.js FOCUS`, `scene.js FOCUS_DARK`. 어둡게 할 재질은 **물건 단위로 기억**(`envMats`) — 물결 효과가 재질을 바꿔 끼우기 때문.

## 6. 동기화 규칙
- **방장**이 공 궤적·판정·점수를 계산해 `{k:'ev', ev}`, 참가자는 입력만 `{k:'in', kind:'toss'|'swing'|'late', t, dir, up, from}`. 시각은 모두 **방장 시계**(참가자는 `game.offset` = ping 최소 왕복으로 변환).
- 참가자는 자기 타격을 `computeShot`으로 먼저 보여 주고, 방장 결과가 오면 맞춤. 방장은 원격 입력을 0.45초 더 기다림.
- **늦게 온 타격은 공 출발을 늦춤**: 방장에게 늦게 도착한 스윙은 공이 라켓에 더 머물다 출발(`match.swing(..., now)`, 도착 때 날아간 시간 ≤ `LATE_OK` 0.15초).
- **와이파이 느림 대비**:
  - ① 받는 사람 쪽 지연만큼 출발 늦추기: 참가자가 ping에 `lat`(최근 왕복 12개의 75% ÷ 2, `room.js typicalLag`)를 실음 → `Match.lagOf` → hold에 최대 `RECV_LAG_MAX` 0.2초 더함.
  - ② **네트워크 렛**: 'shot'을 받았을 때 공이 이미 `LET_LATE` 0.3초 넘게 날아갔으면 `late`를 보냄 → 그 공을 놓치면 실점 대신 `let`(같은 서버가 다시 서브). 선수마다 한 경기 `LET_MAX` 3번까지. 토스트 '📶 … 연결이 늦어서 다시 서브!'.

## 7. 연결 — 서울 중계(TURN) · WebRTC
- 교실 와이파이는 **기기끼리 막혀서**(AP 격리, 11/25 확인) 직접 연결은 안 되고, 싱가포르 Supabase 경유는 왕복 약 160ms. **Cloudflare 서울 중계(TURN)**는 약 35ms(교실 측정 11/25) → 게임에 적용.
- `src/net.js joinRoom(..., { rtc: true })` + `makeP2P`: 경기 채널로 offer/answer/ice(`{k:'_rtc'}`)를 주고받아 선수끼리 DataChannel. id 작은 쪽이 걸고, 9초 안에 안 열리면 다시(3번까지), 먼저 온 ice는 모아 둠.
  - **모든 소식을 서버 채널과 직접 길 둘 다로**(`_f`·`_s` 번호) → 받는 쪽 `fresh()`가 먼저 온 것만. 그래서 연결이 안 붙어도 그대로 서버로 경기, `room.js` 메시지 처리는 그대로. 관전(listen)·광장·로비 채널은 서버만.
  - 켜는 곳 `room.js useRtc` = 경기 채널 사람 2명 이상(4명이면 서로 다 연결, 김제빵은 연결 없음).
- **출입증**: `api/turn.js`(Vercel 서버 함수 `GET /api/turn`) — Vercel 환경 변수 `CF_TURN_KEY_ID`·`CF_TURN_API_TOKEN`으로 4시간짜리 iceServers(UDP·TCP 3478·TLS 443), 설정 없으면 503. `net.js loadTurn()`이 페이지를 열 때 받아 두고 만료 30분 전이면 새로. `iceServers()` = 구글 STUN + 중계. 주소를 아는 누구나 받을 수 있지만 4시간 기한 + 무료 월 1,000GB라 받아들임(사용자에게 설명함).
- 경기 화면 왼쪽 위 `#net-pill`: '⚡ 직접 연결' / '⚡ 서울 중계' / '⚡ 직접·중계' / '⚡ 일부 연결 (n/of)' / '🌐 서버 경유'. 누르면 진단 `#net-diag`(상대마다 시도·주소 종류·상태·추정 이유·출입증 있음/없음), 콘솔 `[직접 연결]`, `__smash.room.link.rtcInfo()`.
- 시험: `?rtc=0` 직접 길 끔 · `?turn=0` 중계 끔 · `?lag=80` 서버 길 지연(직접 길은 안 늦어서 렛 시험은 `?rtc=0&lag=700`). 로컬·점검(ONLINE 아님)은 /api/turn 안 부름.
- 측정 페이지 `rtc-test.html`(+ `src/rtcTest.js`, 게임과 무관): 서버 경유·직접·서울 중계 왕복 시간 비교. 와이파이가 바뀌면 다시 재 보려고 남겨 둠(중계 길은 주소 끝 `#turn=<base64url iceServers>`일 때만).
- 안 하기로 함: Supabase 서버 지역 옮기기.
